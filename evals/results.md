What the eval found and what changed:

- Count and weight lines written without a `$` (`4 @ 0.99`, `1.6 lb @ 4.00/lb`) were ignored, so a 1.6 lb item counted as 1 item (qty/unit match 87.5% on the first run). Fixed by making the `$` optional in both copies of the regex (`mcp/penthouse_mcp/receipts.py`, `scripts/lidl_sync.py`).
- A payment block that starts with `VISA ****9999` instead of `Card` was not cut, so the card digits, auth code and approval number stayed in the text. Fixed by adding card brands and `Auth`, `Approval`, `Tender` to the cut list in both copies. The leak count above is measured on the cut text and the payload of every case.
- Still open: an item name wrapped over two lines (`ORGANIC BABY SPINACH` then `ENTREE 3.29 F`) is read as the item `ENTREE`, so recall is 94.7%. Not fixed, because I haven't seen a real Lidl receipt wrap names.

Cases with misses right now: `07-hard-layouts.txt`

Limits: the cases are made up by me in the layouts the app handles, so these numbers say the parser does what I designed it to do, not how it does on every real receipt. The Claude paths (receipt photos, `estimateItems`, size guessing) are not evaluated here yet: they need receipt screenshots and API spend.
